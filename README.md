## Releases and Hub publication

Repository releases generated by release-please update the changelog and GitHub
release metadata. They do not publish Hub modules. In particular, a `v*` tag does
not publish every Userspace package or assign one version to unrelated modules.

Use the **Publish one Userspace module** workflow with a single package directory
(for example, `docker`, `src/uploads`, or `src/user`) and an explicit Hub version.
The selected directory's `wippy.yaml` determines the module ID: `src/user`, for
example, publishes `userspace/users`. The repository root, aggregate `src` tree,
and nested test workspaces are rejected.

The workflow defaults to a dry run: it packs that module without uploading and
does not receive Hub credentials. Actual publication requires selecting master,
setting `dry_run` to false, and configuring a publish-scoped `WIPPY_TOKEN` secret
accessible to this repository. A missing token fails before invoking the CLI.
Each run publishes only its selected module, using the verified Wippy runtime and
native `wippy publish` command; it does not scan the repository for other modules.

When a new package is a dependency of another, publish it first. For the Docker
client extraction in #69, publish `docker-client 0.1.0` after that PR lands, then
`docker 0.5.18`. The repository's `0.6.0` release number is separate from both.
